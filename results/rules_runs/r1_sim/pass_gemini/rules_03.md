===RULES===
1. Output exactly one line: the rewritten instruction itself, and nothing else — no headings, labels, bullet points, quotation marks, reasoning, or notes of any kind (never text like "Thinking Process:"). If unsure what to write, copy the input instruction unchanged rather than output anything else.
2. If the instruction is already a short direct command — it starts with a base-form verb (like "put", "take", "fold"; not "moved", "puts", or "putting") or is a terse caption fragment (like "put pan in sink", "lever vertical to front"), runs under about 15 words, and contains no "please", "kindly", "I", "me", or "you", and no multi-word description standing in for an object's name (colour plus a plain vague noun, like "the orange vegetable" or "the green thing", is a name, not a description) — output it exactly as given: do not add or remove articles, fix spelling or grammar, change capitalisation or punctuation, or swap any word for a synonym. Exception: an instruction whose main verb is transfer, shift, carry, bring, relocate, transport, convey, or deposit is not already in the right form even when short — rewrite it like any other instruction, normally by swapping that verb for "put" or "place" and fitting the goal with "on" or "in" ("Transfer the carrot over to the wheel." → "put the carrot on the wheel"). Second exception: an instruction that begins "Pick up X and …", where the only place named is the final destination Y, collapses to its final clause alone, keeping that clause's exact words and adding nothing ("Pick up the carrot and set it down on the keyboard." → "set the carrot down on the keyboard."); this never applies to an instruction that opens with any other verb — "Grab X and …" and "Take X and …" freeze exactly as given — and never to an instruction containing politeness words.
3. Rewrite the instruction as a short, plain imperative that keeps the same objects and goal.
4. When a multi-word description stands in for an object's name, replace it with the everyday one-word name it identifies ("the handheld implement for lifting food" → "the spatula"); if the description fits several objects, pick the most ordinary kitchen word that fits ("the handled cooking vessel" → "the pot"), never keep the ornate description, but never shorten an object's name past the point where it says what the thing is — a description of a cola can becomes "the coke can" or "the red can", not "the can". Replace a rare or specialist object name with the ordinary everyday word for the same thing — "ramekin" → "bowl", "aubergine" → "eggplant", "crockery" → "dishes" — but never swap between two ordinary names ("plate" never becomes "dish", "cloth" never becomes "towel"). When the instruction already names something in one or two plain everyday words — even vaguely, like "object", "thing", "vegetable", or "robot hand" — keep those exact words and substitute nothing. If you cannot tell what object is meant at all, copy the whole instruction unchanged.
5. Never drop or change a stated colour, size, number, material, or position word, and keep both sides of an "or" choice — "the silver lid on the silver pot" keeps both "silver"s, "the little spoon" keeps "little", "pot or pan" never becomes just "pot". Never add one either: no colour, size, number, or location the instruction does not state. Only politeness, conditions ("if…", "provided that…", "assuming…"), and leftover words of a description you have already replaced may be dropped ("the orange, cone-shaped vegetable" → "the orange carrot": the colour stays, "cone-shaped" goes). A texture or material word attached to a name you replaced is not a leftover — it stays ("the woven textile" → "the woven cloth").
6. Keep the small words of any part that is already plain — "lift the pot up out of the sink" keeps "up", "take the lid off" keeps "off". A verb that is already common — set, lay, grab, drop, rest, slide, stack, leave, and the like — is kept, never swapped for a synonym. When replacing an ornate verb, use the first common one that fits: put, place, take, pick up, move, open, close, fold, unfold. Replace bookish prepositions with everyday ones: "atop" → "on top of", "upon" → "on", "within" → "in", "beneath" → "under"; and drop the wrapper "the surface of" — "onto the surface of the plate" → "on the plate". When rewriting, produce one single command, never the two-part "pick up X and put it on Y": if the instruction names a real starting place, keep it in the form "move X from A to B" ("move the carrot from the table to the plate"); if it names no starting place, or only a vacuous one ("its current location", "where it sits", "its current station"), drop the source and write "put X on Y".
7. When the instruction is about moving the robot's own hand, gripper, or arm itself — nothing being picked up, carried, or placed — rewrite it as the caption "end effector transition from X to Y", reusing the instruction's own words for the start and end points ("Transfer the robot hand from the first piece to the second one." → "end effector transition from the first piece to the second piece"); never write "hand", "gripper", or "arm" for the robot's manipulator, and never reword an instruction that already says "end effector".
8. If the instruction is a plain direct command wrapped only in politeness — "please", "kindly", "Can you … for me?", "Could you …?", "I would like you to …" — output it exactly as given, politeness and all: do not strip the wrapper, and change nothing else. A polite instruction whose core is a plain command is never collapsed, split, or reshaped. Politeness words are only dropped when the rest of the instruction needs rewriting anyway.
